# Collaboration guidelines

## Shared voice

- Write public project copy from our shared perspective. Prefer “we,” “us,” and
  “our” over language that presents the work as belonging to one person.
- Treat the website as a record of work we are doing together. Use singular
  attribution only when a source, quotation, or individual action genuinely
  requires it.

## Journal practice

- Keep the website journal chronological and date every entry.
- After a meaningful project conversation, create or update that day’s entry
  with what we tried, what we learned, what changed, and what remains open.
- Keep synthetic results, captured model data, compiled workloads, and measured
  benchmarks clearly distinguished in every entry.

## Commit practice

- After each completed user–Codex conversation that changes this repository,
  run the relevant checks and create a focused git commit for that conversation.
- Commit only the files changed for the conversation. Preserve and do not stage
  unrelated work already present in the worktree.
- Use a concise commit message that describes the shared outcome.
